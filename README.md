# Qt Shell – Blender UI in PySide6

A Blender 4.2+ add-on (Windows, Linux, macOS) that replaces the Blender interface with a Qt window.

## Installation

0. Download `qt_shell.zip` from [Releases](https://github.com/xmoner/blender-qt-shell/releases).
   (The zip from *Code → Download ZIP* cannot be installed by Blender – it contains the whole repository.)

1. Blender → Edit → Preferences → Add-ons → ▾ → **Install from Disk…** → `qt_shell.zip`.
2. Enable the **Qt Shell** add-on.
3. In the add-on preferences click **Install PySide6** (downloads `PySide6-Essentials` into
   Blender's user scripts folder; no admin rights needed). Blender does not respond while it
   installs.
4. Start it with **Window → Open Qt Shell** or F3 → "Open Qt Shell".
   The *Start Qt Shell when Blender starts* option opens it automatically every time Blender starts.

## What runs in Qt

| Part | How it works |
|---|---|
| 3D viewport | Blender renders the scene into a GPUOffScreen (`draw_view3d`) and the image is shown in Qt. Navigation (MMB / Alt+LMB orbit, Shift pan, Ctrl/wheel zoom, touchpad), numpad views 1/3/7/0/5/9, 2/4/6/8 rotation in 15° steps (Ctrl = pan), click and box selection, G/R/S with X/Y/Z axes and numeric input, Shift+D, X/Delete, Shift+A, H/Alt+H, Tab, Z (shading), right click = context menu. **Fast Material Preview like Blender's own viewport**: while the view moves (orbit / pan / zoom, G / R / S, dragging values, playback) EEVEE draws 1 sample, the full Viewport Samples once things settle; optional lower *Navigation resolution* for slow GPUs (Qt Preferences → Viewport) |
| Menus | File, Edit, Add, Object, Select, Render and Help are generated **from Blender's original menus** (including add-on entries), depending on the mode |
| Cached playback | Like Maya: **geometry cache** (default) – the animated geometry and rig controls of each frame are stored and drawn by Qt Shell, so the **camera can move freely** during cached playback (solid shading incl. textures); **image cache** mode for the exact look incl. materials. Green line in the Timeline shows cached frames; Cache button + menu (mode, Cache All Frames, Flush Cache, Memory Limit); **Auto** = background caching while you are idle (paused while you move the mouse, scroll or type – the UI stays smooth), no playback needed; the cache drops itself when the scene changes |
| Keyboard shortcuts | Edit → Keyboard Shortcuts…: every Qt Shell shortcut in one window (window, 3D View, Edit Mesh, Pose, Graph / Node / UV / Text editor) – search by name or key, change, add alternatives, clear, reset; conflicts marked; tooltips and menus always show the current keys |
| Maya & Blender key sets | 3D View keys come in two sets that follow the chosen controls: **Blender** (G/R/S, I, A, Alt+A, H, Tab, Z pie, numpad views …) and **Maya** (Q/W/E/R tools, S key all, Shift+W/E/R key location/rotation/scale, F/A frame, 4/5/6 wireframe/solid/material, Ctrl+H / Alt+H / Ctrl+Shift+H hide, F8 edit mode, F9/F10/F11 vertex/edge/face, Ctrl+E extrude, Ctrl+D duplicate). Each set is edited on its own in Qt Preferences → Shortcuts (or Interface → Navigation & Shortcuts) |
| Navigation | Blender or Maya mouse navigation in the 3D view (Qt Preferences → Interface): Maya = Alt+left tumble, Alt+middle track, Alt+right dolly, middle drag with the active tool |
| Recent files | File → Open Recent (also Ctrl+Shift+O): the last 20 opened / saved files, newest first, like Maya's Recent Files; Qt Shell keeps its own history next to Blender's |
| Properties | The Render, Output, Scene, World, Object, Data, Material, Physics… tabs are generated **from Blender's original Python panels** through a stand-in `UILayout` The tab column on the left shows the full names, its width can be dragged (remembered) and it scrolls when it is narrow or short. **Search** (field above the tabs, Ctrl+F like Blender): finds property names, labels, buttons and texts in all tabs – panels without a match are hidden, panels with one open, matches are highlighted, tabs without a match are greyed out (the tooltip shows the number of matches); Esc clears it. Custom Properties: **Edit Property** opens a Qt dialog like Blender's (type, name, default, min / max, soft limits, step, precision, subtype, description, library overridable) and applies it with Blender's own operator code. |
| Modifiers, constraints | Own Qt version (Blender draws these in C), including Geometry Nodes inputs; Add Modifier menu with categories, icons and a modifier-only Search… |
| Outliner | Blender's View Layer outliner with Maya's conveniences: display modes **View Layer / Blender File / Orphan Data** (Purge); restriction columns Exclude, Selectable, Hide in Viewport, Disable in Viewports / Renders, Holdout, Indirect Only – click, **drag across rows**, Ctrl+click isolates, Shift+click includes children; filter menu (columns, sort, sync selection, collections / objects / contents / children, object types, object state, invert); search with wildcards `*` `?` (Maya), exact / case options; collection colour tags; hidden objects greyed (Maya); drag & drop (left or middle mouse) to parent, drop on a collection to move (Ctrl = link), drop on empty space to unparent; context menus for objects and collections (select hierarchy, delete hierarchy, duplicate / instance collection, visibility, view layer, colour tag…); object contents (animation, data, bone hierarchy, materials, modifiers, constraints, vertex groups); follows the viewport selection; 21 keys (F show selected, Home hierarchy, Numpad +/− levels, A / Alt+A / Ctrl+I, F2, X, H / Alt+H, C, M / Shift+M, E / Alt+E, P / Shift+P, Ctrl+F / Alt+F), all editable in the Keyboard Shortcuts window; new icon set; clicking an object while a rig is in Pose / Edit Mode leaves the mode and selects it (like Blender); unselectable objects (Selectable off on the object or its collection) show the reason in the status bar; in Edit Mode Ctrl / Shift + click on more meshes edits them all together (multi-object editing, also in the UV editor); **Duplicate Collection** copies like Blender (a rig's copy uses its own armature, drivers, constraints and custom shapes; collection and object visibility / selectability kept) |
| Render View | Like Blender's render window (a separate window or – **Dock** button – docked in the Qt Shell window like any editor: drag it to any side, tab it, float it): **F12** renders and opens it (the picture updates about once a second while rendering, with the elapsed time), **F11** shows / hides the last result. Header: **View** menu (Sidebar, Zoom In / Out, Fractional Zoom 1:8…8:1, Frame All, Next / Previous Slot), **Image** menu (Render Image, Save, Save As – PNG, JPEG, OpenEXR, OpenEXR MultiLayer, TIFF, WebP, BMP – Save a Copy, Copy to Clipboard, Edit Externally), Render Result, **render slots** 1–8 (J / Alt+J; the next render goes into the active slot, each slot keeps its metadata), **View Layer and Pass** (all passes enabled in View Layer Properties → Passes – Depth / Mist normalised, Normal as colours), **Display Channels** (Color & Alpha with a checkerboard, Color, Alpha, Red, Green, Blue), zoom and sidebar, **Gizmos** (navigation gizmo: drag the zoom / pan buttons) and **Overlays** toggles. **Toolbar** on the left (T) like Blender's Image Editor: **Sample** (left mouse samples the pixel – linear R G B A + the displayed values, X / Y from the bottom-left like Blender) and **Annotate** (Annotate / Annotate Line / Annotate Polygon / Annotate Eraser – hold or right click the button; notes per render slot, colour and thickness in the header, Ctrl+Z undoes, View → Clear Annotations). Canvas: wheel zooms around the mouse, middle mouse pans. Stats line top left; sidebar (N): Image and Metadata (frame, render time, date, scene, camera, lens, engine, samples, file). All keys in the Keyboard Shortcuts window (*Render View*); `qt_shell.api.render_view()` from a script |
| Animation Player | **Render → View Animation** (Ctrl+F11) opens Qt Shell's own player (a separate window or – **Dock** button – docked in the Qt Shell window; the dock can be made small – the controls row then scrolls with the mouse wheel) instead of Blender's separate window (which disappeared behind Qt Shell): plays the rendered frames of the scene range (preview range when on) from the Output path – PNG / JPEG / TIFF / WebP / BMP, OpenEXR via OpenImageIO; movie files with Qt Multimedia. **Timeline** with frame numbers, loaded frames (green) and the current frame – click / drag to scrub, wheel steps; transport (first, step back, play backwards, play, step forwards, last), loop mode (Loop / Play Once / Ping-Pong), **Synced** button (connected to the Timeline: scrubbing / playing in the Timeline shows the same frame in the player, scrubbing / stepping in the player moves the scene's frame, Play / Pause drives the Timeline's playback; frames outside Start – End are reported), **Start / End** fields (any frames to play – drag or type; the clock button goes back to the scene range), playback speed (scene fps or 12 … 60 fps), **Update Animation** button (R / F5 – reads the rendered images again after a new render or changed Output settings; an open player also updates by itself when Render Animation finishes; Start / End follow the scene range unless you changed them); wheel zooms the image, middle mouse pans, F fits. Keys: Space play, Shift+Space backwards, Left / Right step, Shift+Left / Right or Home / End first / last, Esc closes. The window always stays in front of the Qt Shell window |
| Render progress & cancel | While **Render Animation** runs, the Timeline playhead (and frame field) follows the frame being rendered and the status bar shows *Rendering frame N (i / total)*; Blender puts the scene frame back afterwards. A running render (image or animation) can be stopped with **Esc** (main window or Render View), the **Cancel Render** button in the status bar or the Render View header, or **Render → Cancel Render** (under Render Animation). A cancelled image keeps what was rendered so far |
| Rigs | Object mode: clicking a rig control enters Pose mode and selects it (like Maya; can be turned off in Qt Preferences); in Pose mode a click on another rig's control moves Pose mode to that rig. Pose mode: click / Shift+click / box selection of bones by their custom shapes (rig controls) or bone lines; moving / rotating / scaling bones with G / R / S (axis, numbers) or the gizmos, keys with I / Alt+I (and the Timeline / Graph editor) on the selected controls, Graph editor and Timeline show only the selected controls' keys, auto-keying, Alt+G/R/S clear, A / Alt+A / Ctrl+I, H / Alt+H, pose context menu; Object mode: curves and armatures are hit by their lines |
| Timeline | Blender's Timeline + Maya's Time / Range Slider. ## Python API for add-ons (`qt_shell.api`)

**Full reference: [`docs/API.md`](docs/API.md)** – every function, event and example.

Development notes, status and open issues: [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).

Most add-ons need nothing special: Qt Shell runs Blender's own UI code, so these appear in Qt automatically:

- **Properties editor panels** (`bl_space_type = 'PROPERTIES'`),
- **3D viewport sidebar panels** – the N panel (`bl_space_type = 'VIEW_3D'`, `bl_region_type = 'UI'`), one tab per `bl_category`,
- **menu entries** appended to Blender menus (`bpy.types.VIEW3D_MT_add.append(...)`, `TOPBAR_MT_file`, …),
- **operators** (menus, F3 search, panel buttons).

For things that only exist in Qt Shell, use the API (`API_VERSION = (1, 7)`):

```python
import qt_shell.api as qs

qs.is_running()                       # True when the Qt window exists
qs.status("Done", timeout_ms=4000)    # status bar message
qs.status_history()                   # [('19:25:59', 'Done'), …] – also: click the status bar

# dockable panel – the factory is called on every window (re)build
def make_panel():
    from PySide6 import QtWidgets
    return QtWidgets.QPushButton("Top view", clicked=lambda: qs.set_view("TOP"))
qs.add_dock("my_panel", "My Panel", make_panel, area="left")      # left/right/bottom/top
qs.remove_dock("my_panel")

# menu items – existing menus ('File', 'Object', 'View', 'Window', …) or a new one ('Tools')
qs.add_menu_action("Tools", "Say Hello", lambda: qs.status("Hello"), shortcut="Ctrl+Alt+H")
qs.remove_menu_action("Tools/Say Hello")

# 3D view
qs.get_view()        # {'target': (x, y, z), 'distance', 'yaw', 'pitch', 'ortho', 'camera_view', 'name'}
qs.set_view("TOP")   # FRONT/BACK/LEFT/RIGHT/TOP/BOTTOM/CAMERA
qs.set_view(target=(0, 0, 1), distance=10, yaw=0.8, pitch=1.1, ortho=False)
qs.frame_all(); qs.frame_selected(); qs.redraw()
qs.project((1, 2, 3))           # world → (x, y) pixel in the viewport, or None
qs.view_matrix(); qs.projection_matrix(); qs.viewport_size()
qs.set_viewport_layout("quad")  # single / side / stacked / quad – view functions act on the active view
qs.viewport_layout(); qs.viewports()

# drawing over the viewport with QPainter
def draw(painter, ctx):          # ctx.width, ctx.height, ctx.project(co) → QPointF | None
    for ob in bpy.context.visible_objects:
        p = ctx.project(ob.matrix_world.translation)
        if p is not None:
            painter.drawText(p, ob.name)
qs.add_overlay("names", draw)
qs.remove_overlay("names")

# events: data, selection, frame(frame), mode(mode), file, undo, render,
#         operator(idname, props, result), playback(playing), window(main_window),
#         script(key, state)
h = qs.on("frame", lambda frame: print("frame", frame))
qs.off(h)

# ownership – remove everything an add-on registered in one call
with qs.owner("my_addon"):
    qs.add_dock(...); qs.add_menu_action(...)
qs.owned("my_addon")      # [('action', 'Tools/Say Hello'), ('dock', 'my_panel')]
qs.cleanup("my_addon")    # e.g. in your add-on's unregister()
```

Everything registered is kept when the Qt window is rebuilt (Interface Size, add-on reload) and can be
registered before Qt Shell starts. Callbacks run on Blender's main thread with a valid context; errors are
written to the log instead of breaking the UI. The module does not need PySide6 to be imported, so an add-on
can use it optionally:

```python
try:
    import qt_shell.api as qs
except ImportError:
    qs = None
```

A complete example is [`examples/api_demo.py`](examples/api_demo.py) – open it in the Text editor dock and press Alt+P,
then **■ Unload** to remove it again.

### Scripts: run, unload, reload

Write scripts like Blender add-ons – it keeps them easy to turn into an add-on later:

```python
def register():
    ...            # register classes, handlers, Qt Shell docks / menus / overlays / events

def unregister():
    ...            # optional in Qt Shell – whatever is left is removed automatically

if __name__ == "__main__":
    register()
```

A script run by Qt Shell (Text editor, Scripts dock, auto-load) owns everything it registers. **■ Unload**
calls its `unregister()` and then removes what is still registered; **Run** on a loaded script unloads it
first, so editing and re-running never leaves duplicate menu items or handlers. Not tracked automatically:
`bpy.app.timers`, keymaps and functions appended to Blender menus (`VIEW3D_MT_…append`) – remove those in
`unregister()`.

How to see which scripts are loaded and how to remove a script (also one set to auto-load on startup): [Which scripts are loaded / Removing a script](docs/API.md#removing-a-script).

## Troubleshooting

- Errors and warnings are also written to `qtshell.log` in the system temp folder
  (Windows: `%TEMP%\qtshell.log`), because Blender's console is hidden.
- If the Qt window can't be created, the normal Blender window comes back automatically.
- A hard crash writes the Python stack to `%TEMP%\qtshell_crash.log`.
- **Floating windows** (a dock dragged out of the main window) are docked before the layout is saved – a saved
  layout with a floating dock crashed Blender on the next start – and float again at their place a moment after Qt Shell starts.
- **Safe start:** if the previous start of Qt Shell crashed Blender, the next start discards the saved
  window layout and opens with the default one.

## Limitations

- The image editor, sculpt/paint brushes, gizmos and viewport header buttons of add-ons are not converted.
- The node editor does not show special node widgets (Color Ramp, curves) – their settings are in
  the sidebar only where they are plain RNA properties.
- The UV editor has its own UV point selection (not synced with Blender's UV selection).
- `template_*` elements without a Qt counterpart are shown as a grey `‹template_…›`.
- The Blender window cannot be hidden under pure Wayland.
- macOS: Qt and Blender share one Cocoa event loop; it works, but it is the least tested platform.
