## 1. What it is

A Blender add-on (`qt_shell/`) that replaces Blender's UI with a PySide6 (Qt) window: 3D viewport,
Properties, Outliner, Timeline, Console, Node editor, UV editor, Text editor, Sidebar (N panel),
menus, operator search. Blender keeps running hidden underneath; Qt drives it through `bpy`.

Tested on **Blender 5.2.0 LTS, Windows 11** (Czech keyboard). Requires Blender 4.2+.

## 2. Architecture – the important parts

| Topic | How it works |
|---|---|
| **Event pump** | `app.py`: a `bpy.app.timers` timer calls `QApplication.processEvents()`; returns `0.0` while playing, `0.01` otherwise. `native.wake_event_loop()` posts `WM_NULL` after processing. |
| **Blender context in Qt events** | `ShellApp.notify` delegates to the module-level `_notify_with_context` (looked up through `sys.modules`), which wraps every Qt event in `bridge.blender_context()` (`temp_override` onto a 3D view). **Never reassign `notify` on a running QApplication** – Shiboken caches the override and the freed function crashes Blender (`<invalid frame>`). |
| **Hidden Blender window** | `native.py`: SW_MINIMIZE then SW_HIDE (otherwise Blender keeps redrawing and waits for VSync → 60 fps cap). |
| **Viewport rendering** | `viewport.py`: `GPUOffScreen.draw_view3d()` with our own camera matrices → numpy → copied flipped into a Qt-owned `QImage` (`img.bits()`). One view = one `Viewport` widget with its own camera. |
| **Split views** | `ViewportArea` (in `viewport.py`): single / side / stacked / quad (Ctrl+Alt+Q). `MainWindow.viewport` is a property = the active view; `hub.viewport` follows the active view, `hub.viewport_area` is the area. Shading is shared (Blender's space). |
| **Playback** | `Timeline.playback_tick()`: time-based, follows `scene.sync_mode`; `ViewportArea.render_now()` draws every visible view. ~117 fps at 120 target. |
| **UI from Blender's Python UI code** | `fake_ui.py` records `Panel.draw` / `Menu.draw` calls; `qt_ui.py` builds Qt widgets from the recording; `rna_widgets.py` binds widgets to RNA properties. Properties pages build atomically and each panel is wrapped in try/except (one broken panel shows an error, the tab still works). |
| **Public API** | `api.py` (`import qt_shell.api as qs`), version 1.2. Registry lives in `api.state_store()` = a module `_qt_shell_state` in `sys.modules` (survives add-on reloads and loading other .blend files). Full reference: `docs/API.md`. |
| **Script manager** | `scripts.py`: runs scripts, records what they register (API items, `bpy` classes, `bpy.app.handlers`), Unload / Reload, auto-load (files in `config/qt_shell/scripts.json`, texts with custom prop `qtshell_autoload`). No PySide in this module. |
| **Text editor** | `text_editor.py`: `CodeEditor` (QPlainTextEdit) + `TextEditor` dock on `bpy.data.texts`. Auto-completion logic in `completion.py` (pure Python, no code execution) – popup = `QCompleter`, names in `Qt.UserRole`. |
| **Transform tools / gizmo** | `gizmo.py`: `ToolState` (shared tool + toolbar visibility, QSettings `viewport/tool`, `viewport/toolbar`, stored on `hub._tool_state`), `Toolbar` (child of each `Viewport`), `handles()` (ids "G:X", "R:VIEW", "S:UNIFORM", …) / `hit()` / `paint()` in screen space, `ToolMenu` (Shift+Space), `start_drag()` → `Viewport.start_modal()` with the axis set and `m['drag']=True` (mouse release confirms). Pivot = median of selected origins / selected verts (edit-mode pivot cached, invalidated on data / selection change). Constrained G follows the projected axis on screen. |
| **Built-in items in Blender menus** | Menus generated from Blender call `api.extend_menu()` when they open; it calls `MainWindow.extend_builtin_menu(menu, key)` first (e.g. inserts *Qt Preferences…* after Blender's *Preferences…* in Edit), then the API items. |
| **Theme** | `theme.py`: `qss()` app stylesheet, `px()` / `fs()` scaling, `HOVER` colours + `hover_qss()` / `field_hover_qss()` (append them to any widget stylesheet that sets a button / field background, otherwise the hover effect is hidden). |
| **Logs** | `%TEMP%\qtshell.log` (errors/warnings), `%TEMP%\qtshell_crash.log` (faulthandler – note: it also logs harmless first-chance access violations, e.g. inside the Windows file dialog). |
| **Safe start** | `app.start()` writes `%TEMP%\qtshell_starting` before building the window and removes it 3 s after `show()`. If it exists on the next start, the saved window layout (`QSettings("QtShell","QtShell")` → `state`, `geometry`) is discarded. |

### Lessons learned (avoid these bugs again)
- `GPUOffScreen.draw_view3d` does **not** run `SpaceView3D.draw_handler_add` callbacks (POST_VIEW never fires), but it leaves the scene depth in the offscreen's depth buffer – draw own things after it with `offscreen.bind()` + depth test LESS_EQUAL (and a small bias towards the eye for surfaces on the same mesh).
- blicons: never add an attribute that `_s()` already sets (stroke-width …) – a duplicate attribute makes the SVG invalid and Qt silently draws an empty icon. Pass it to `_s(color, width)` instead; check all icons with an XML parser after adding some.
- `setIconSize()` on a button is undone by the app stylesheet's `qproperty-iconSize` when the widget is polished – give the button its own stylesheet with `qproperty-iconSize` instead. QIcon never scales a pixmap up: add pixmaps of the size you show.
- Never let a Blender **modal** transform run (INVOKE of a transform macro such as mesh.extrude_region_move, or a Python operator that invokes one) – it runs in the hidden 3D view and crashes in recalcData_mesh. Run the macro's first operator, then Qt Shell's own G / R / S (main_window.special_op / `_macro_parts`).
- Don't keep `BMLoop` / `BMFace` references across Qt events (e.g. during a mouse drag): the edit BMesh can be rebuilt by a redraw and writes to old references silently go nowhere. Keep indices and call `bmesh.from_edit_mesh()` + `ensure_lookup_table()` on every write.
- Blender 5.x UV editor: `area.ui_type = 'UV'` (no `SpaceImageEditor.ui_mode` 'UV'); UV selection lives on `BMLoop.uv_select_vert / uv_select_edge` and `BMFace.uv_select` (the `*_set()` methods flush – a face set False deselects its corners); in sync mode call `bm.uv_select_sync_from_mesh()` after changing the mesh selection, otherwise UV operators use a stale UV selection.
- Don't put a style sheet on spin boxes / combo boxes to highlight them – it switches them to style-sheet rendering and changes their size; colour the label instead.
- Overlays of the offscreen draw follow the hidden region's `region_3d.view_perspective` – set it to CAMERA in our camera view, otherwise Blender draws the camera we look through.
- Blender popovers like Overlays / Shading draw most of their content in sub-panels (`bl_parent_id`) – a popover needs the parent's draw() **and** its children.
- Things measured from the selection for a transform (snap source points) must be captured when the modal starts – later the objects / vertices have already moved.
- A widget inside a LazyMenu (QWidgetAction) is deleted whenever the menu is refilled (also by code that emits `aboutToShow`) – start timers on it with the widget as the context: `QTimer.singleShot(0, widget, fn)`.
- Don't rebuild (delete) a widget inside its own signal (e.g. a combo's `activated` that rebuilds the form) – defer with `QTimer.singleShot(0, …)`.
- Operators whose `execute()` depends on state set in `invoke()` (e.g. `wm.properties_edit`) can't run from Qt as EXEC. Build a Qt dialog and run the operator class's Python methods on a stand-in object; take the settings from `bpy.ops.<op>.get_rna_type().properties` – the class `bl_rna.properties` may miss some.

- **QImage.save fails silently when the folder doesn't exist** – `os.makedirs` first.
- **`devreload` wipes the Console namespace** – keep test snapshots of shared settings in a file, not in a Console variable, before reloading.
- **Blue Pencil data = JSON in a scene ID property** (`scene["qtshell_bluepencil"]`): saved with the file and part of Blender's memfile undo – every edit `commit()`s + `undo_push`, `data()` re-parses when the raw string changed (undo, file load). Coordinates are normalised by the frame height (camera frame from `cam.data.view_frame()` projected, or the view) – note the Qt Shell camera view fits the camera frame to the widget width (it can be cut at the top / bottom).
- **A synthetic two-point drag never reaches the middle** – the eraser sweeps between mouse positions now.
- **The Render Result can't be read from Python while rendering:** `Image.pixels` is empty, `save_render` fails, `gpu.texture.from_image` returns a 1×1 dummy (no image user), `image.save_as` polls False (Render Result's source is VIEWER). Qt Shell's live preview: the hidden render helper window holds an Image Editor showing Render Result; hidden but **not minimized** (Blender skips drawing minimized windows), forced to draw with `wm.redraw_timer(DRAW_WIN_SWAP)`, captured with `screen.screenshot_area` (front buffer) and cropped by `SpaceImageEditor.zoom` (image zoomed with a margin – the editor draws render info over its top).
- **A render shorter than one hub tick never emitted render_done** (is_rendering was never seen True) → the Render View kept the old picture. The main window now polls `bridge.is_rendering()` itself while `_rendering`.
- **`wm.redraw_timer(DRAW_WIN_SWAP)` restores a GPU context right away** after a window was closed (wm_draw_update's fallback makes a window drawable when none is) – the WM_PAINT / time hold alone still crashed.
- **Cancelling a render from Python:** `render.render` (INVOKE) adds its modal handler to the window it was started from; Esc there is the only key, and Esc can't be sent to Blender (GHOST reads keys via raw input – posted WM_KEYDOWN is ignored; no `G.is_break` in Python). The job is killed when that window closes (handler removal → `screen_render_cancel` → `WM_jobs_kill_type`). So Qt Shell starts renders from a hidden helper window (`wm.window_new`, render display NONE) and closes it to cancel / after the render.
- **Closing a Blender window leaves no GPU context active** (`wm_window_ghostwindow_destroy` clears the drawable) and minimized windows are never drawn, so it stays that way → the next `GPUOffScreen.draw_view3d` crashed in `GLFrameBuffer::bind`. After closing a window: `bridge.hold_gpu()` (is_rendering() True for 0.25 s) and `native.repaint_blender_windows()` (WM_PAINT → GHOST WindowUpdate → `wm_window_make_drawable`).
- **During an animation render `scene.frame_current` changes** (main-thread readable); Blender restores it at the end.

- **Blender 5.x multilayer EXR = multi-part file**: one part per render pass. With OpenImageIO loop `inp.seek_subimage(i, 0)` over all parts, otherwise you only get the first pass (Combined).

- **Testing with a floated dock:** `devreload` / closing the window saves the layout (`state`) – with a floated dock the owner's next Qt Shell start comes up with it floating. Dock it back (`setFloating(False)`) before every reload.

- **Outliner selection sync vs. drag:** don't rewrite the tree selection while a mouse button is down in it – Qt only starts a drag when the pressed row is still selected. `Outliner.sync_selection` postpones itself (`_sync_pending`) until release / drop.
- **QMenu:** checkable actions with an icon show no check mark, and `addSection` text is not drawn in the Fusion style – use `QWidgetAction` rows (`outliner._check_item`, `_section`).

- **Give every Qt widget its parent when you create it.** Widgets added to a layout that is not yet
  installed on a widget can be freed by Python → access violation when the window is shown.
- **A widget-level stylesheet overrides the app stylesheet for that widget and its children** – add
  `theme.hover_qss()` to it. Mixing a selector-less declaration with rules in one sheet is invalid:
  use `QWidget { … }`.
- **`QStandardItem`: `EditRole` == `DisplayRole`.** Use `Qt.UserRole` for data that differs from the label.
- **Zoom limits must clamp, not refuse** (Node editor wheel bug). Don't frame/fit a view while it is
  hidden or tiny – defer until it is visible (`NodeView._big_enough()`, `_frame_pending`).
- **Styling `QMenu::item` disables the default selection highlight** – style `:selected` explicitly.
- **Dropping text dragged from a QPlainTextEdit: force `Qt.CopyAction`** – the default is Move, which deletes the
  text from the editor.
- **Never save a layout with a floating dock.** Restoring a `QMainWindow` state that contains a floating
  `QDockWidget` crashes Qt on Windows in `show()` (execute access violation at a bogus address), even if the
  dock is docked again right after `restoreState()`. Floating at run time is fine. `MainWindow.shutdown()`
  docks floating docks before `saveState()`; restored floating docks are docked too (`api._install_dock` as well).
  This was the cause of the recurring "previous start did not finish" crashes (2026-10-19/20).
  To keep floating windows across restarts, `shutdown()` stores their geometry in QSettings `floating_docks`
  (JSON) before docking them, and `MainWindow._float_saved_docks()` floats them again **1.5 s after the start**
  (tested OK; re-floating right after `show()` crashed). Safe start also clears `floating_docks`.
  Workspaces follow the same rule: `Workspaces.capture()` docks floating docks, saves the state, then floats
  them again; `_apply()` docks everything, restores, and re-floats 50 ms later.
- **`deleteLater` is never processed by Blender's `processEvents` pump** – a closed MainWindow stays alive
  (hidden). After the workspaces were added, `devreload` crashed in the new window's `show()` (access violation,
  2026-10-20, twice). Fix: `devreload` calls `QCoreApplication.sendPostedEvents(None, QEvent.DeferredDelete)`
  right after `app.stop()` → the old window is deleted before the new one is built (3 reloads in a row OK).
  Plain close (*Return to the Blender UI*) + *Window → Open Qt Shell* worked without it. When poking at the
  window from the Console, pick the *visible* one (`... if hasattr(w, "workspaces") and w.isVisible()`).
- **Restore the saved dock layout only after the window is shown.** Even with no floating docks, `restoreState()` before
  the first `show()` crashed Qt on Windows (17:54, 2026-10-20), while the same call at run time (workspace switch)
  never did. `MainWindow.__init__` now only restores the geometry; `_restore_saved_layout()` runs via
  `QTimer.singleShot(0)` after `show()`. Tested: quit + start with a saved layout OK.
- **Don't re-float docks during shutdown.** 2026-10-20 15:39: crash in `show()` at the next start after closing
  with a floating Text editor; `Workspaces.capture()` had docked + re-floated it while the window was closing.
  Now `shutdown()` collects floating geometry first and `workspaces.shutdown(floating)` captures without re-floating.
- **No Python event filter on the QApplication.** The first Python-tooltip version installed one; after a dev
  reload `notify()` received a `QMoveEvent` as the *receiver* (stale PySide wrappers, hundreds of
  "Error calling Python override of QApplication::notify()") and key events stopped working. Hook into the
  existing `app._notify_with_context` instead (it already runs for every event) and never keep events alive
  in tracebacks. Also: `QtGui.Qt.mightBeRichText`, not `QtCore.Qt`.
- **Re-adding docks (`_reset_layout`) can grow the window** past the screen. Workspace switches remember the
  window geometry and put it back (`workspaces.fit_to_screen`); templates set dock widths with `resizeDocks`.
- **Testing playback from a Console script doesn't advance it** – `Timeline.playback_tick` runs from the event pump (bpy timer),
  which a blocking test loop with only `processEvents()` never reaches; test playback with real waits between Console commands.
- **Never `activateWindow()` on hover without checking who is active** – it brings the Qt Shell window in front of
  every other window (Blender's player, other programs). Use `app.hover_activate(widget)`; extra Qt windows get the
  main window as parent (`QWidget(main, Qt.Window)`) so Windows keeps them above it.
- **Annotations are not in Blender's offscreen drawing** (`GPUOffScreen.draw_view3d` leaves them out, checked
  2026-10-22) – Qt Shell draws `scene.annotation` itself (`annotate.paint_annotations`, numpy projection). In 5.2
  `bpy.data.annotations` is the legacy *Annotation* type (layers: `info` not `name`, `frames.new`, `strokes.new`,
  `points.add`, `point.co`, stroke `display_mode` 3DSPACE / SCREEN with SCREEN in % of the region from the
  bottom left), while `bpy.data.grease_pencils` is GP v3 (`frame.drawing.add_strokes`). An empty
  `bpy.data.annotations` collection is falsy – `annotations or grease_pencils` silently picks the wrong one.
  Rulers (Measure) are strokes of 2 / 3 points in the layer `RulerData3D`, like Blender's.
- **Computer-use note:** the top-right corner of the screen (x > ~1070 in screenshots) belongs to the Claude
  app's overlay – clicks there don't reach Blender. Make the Qt Shell window narrower to click the workspace tabs.

- `bpy.data.libraries.load()` cannot read the .blend that is currently open (`ValueError: Cannot load from the current blend file.`) – append from a temporary copy of it (Append), linking a file into itself is impossible.
- `GPUOffScreen.draw_view3d` renders EEVEE as an image render: **all viewport samples (`scene.eevee.taa_samples`) in every call** (~9 ms per sample here) – draw 1 sample while things move (`viewport.eevee_samples`), full samples when still. Changing a scene setting from Python only reaches draw code after a depsgraph update (`evaluated_depsgraph_get().update()`) – benchmarks that skip it measure nothing. `rv3d.view_matrix` is stale until the region redraws (reading it after setting `view_rotation` gives the old matrix → draw_view3d returns its cached picture in ~2 ms). A new offscreen costs an EEVEE setup – keep offscreens alive.
- A QHBoxLayout row of controls sets the minimum width of its widget (and of the dock around it) – put wide control rows into a wheel-scrolled QScrollArea when the widget must shrink.
- Copying objects with `ID.copy()` doesn't remap references between the copies (modifiers, drivers, constraints, custom shapes) – use `object.duplicate` (relinks within the duplicated set). Objects can only be duplicated when visible and selectable in the view layer; drivers on `hide_*` re-hide them after you unhide them (mute them for the moment, then `view_layer.update()`).
- Background work on the main thread (auto cache, probes) must wait for real idleness – use `app.idle_seconds()` (last mouse / wheel / key event), not just `QApplication.mouseButtons()`. When the UI "stutters", time the main loop first (a 30 ms QTimer that takes 90 ms per tick = something else blocks), not the widget that feels slow.
- Never connect `clicked` straight to a function with an optional first argument (`insert_frame(f=None)`): PySide passes `checked=False` into it. Wrap it: `clicked.connect(lambda _c=False: fn())`.
- Changing AddonPreferences from Python doesn't mark the preferences dirty – auto-save on quit skips them. Set `bpy.context.preferences.is_dirty = True` (Qt Shell: the `_prefs_changed` update callback).

- **A QPainter left active crashes Qt natively later** (access violation in `processEvents`, no Python traceback): an exception in a paint helper (here a missing method) between `QPainter(pixmap)` and `end()` – end painters in `finally`. Also: replacing a live widget's `__class__` after a module reload is risky; patch single methods instead when testing.
- **Fast QPainter drawing of many items:** build paths / polygons once in model coordinates, draw them with `p.setTransform(...)` and **cosmetic pens** (`pen.setCosmetic(True)` keeps the width in pixels), cache the result in a pixmap for panning; deduplicate points drawn with round caps (each costs ~1.5 µs).

- **Blender runs the compositor only when its result is visible** (node editor backdrop or an Image Editor showing "Viewer Node" – an area of a hidden window counts); without that, node changes from Python do nothing. Qt Shell borrows an area for it (image_editor.CompositorLink) and gives it back around saving. The COMPOSITE job is short – watch `bpy.app.is_job_running("COMPOSITE")` often or reload after a timeout.
- `getattr(obj, "collection", None) or fallback` is wrong for bpy collections – an empty collection is falsy (`sequence_editor.strips` → fell back to the removed `.sequences`). Use `hasattr`.

- Blender's compositor computes a picture for Qt only through the **Viewer node** – to show the final result, keep the Viewer linked to what feeds the Group Output (`image_editor.follow_output`). A new Blur node has Size 0 (no visible effect).

- A header style sheet `QWidget { background: … }` overrides the global `QToolButton:checked` colour of every button inside it – add `QToolButton:checked { background: highlight }` to such sheets, or toggles look unchanged.

- Blender's compositor has no Python "run for frame f": to composite an animation, feed rendered raw frames through a temporary Image node (image sequence; `frame_start = scene.frame_current`, `frame_offset = f - 1`) and read the Viewer after each COMPOSITE job. Rendered output files already contain the compositor – compositing them again would apply it twice, so render raw (use_compositing off) OpenEXR first.

- **Removing a node from Python while a Qt item still holds its Python object crashes Blender** (nodes / sockets / links are not IDs – their wrappers are not invalidated, `node.name` may even still work before the next attribute read crashes). Look the node up in its tree by name + `as_pointer()` before touching it, and rebuild views right after structural changes.

- **Blender menus fill operator properties in place**: `props.constraint_axis[0] = True` (Mirror menus) and
  `props.TRANSFORM_OT_edge_slide.release_confirm = False` (macro sub-operators, Loop Cut and Slide). fake_ui.OpProps
  must return a stored list (array defaults) / a nested OpProps for those – returning None broke the whole
  menu draw (Mirror showed only *Interactive Mirror*, the edge context menu ended with an error label).
- **Right-click menu per mode** comes from Blender's key configuration (keymap of the mode → RIGHTMOUSE
  `wm.call_menu` / `wm.call_panel`, viewport.context_menu_id); sculpt / paint / Grease Pencil draw modes use
  panels (PopoverMenu). The old code showed the Edit Mesh menu in every non-object mode.
- **Modal-only operators from menus** (transform.shear / tosphere / push_pull …, mesh.bevel / inset,
  wm.context_modal_mouse, pose.push …) run with EXEC do nothing (value 0) → valuemodal.py. Push an undo step
  *before* the first run: redo = ed.undo + run again, and an edit-mode stack entered from Python has no step
  of its own – undo then jumped back to an older file state.
- **Testing Qt menus from scripts**: patching `QMenu.exec` on the class does not reach PySide subclasses created
  earlier, and copying `cls.exec` after patching the base copies the patch (it never got restored) – close popups
  with a QTimer (`QApplication.activePopupWidget()` / `activeModalWidget()`) instead. Never use `ed.undo` in a test
  loop to reset the scene: stale data crashed Properties (`BlendData_objects_begin`) – rebuild the scene instead.
- `deleteLater()` alone leaves widgets in a layout until Qt's loop runs – remove them from the layout first
  (Adjust Last Operation stacked forms when operators ran from a Blender timer).

- **Redo while dragging**: throttle (start the timer only if it isn't running), never debounce, and never start
  a second `ed.undo` before the previous run finished (`_redoing` + `_pending`). Each redo replaces the object
  (undo + run), so selection / undo signals fire every time – heavy views must wait (`hub.in_redo()`), and the
  3D view must not draw between the undo and the new run (`hub.hold_frame`) – the object blinked.

- A panel that serves several windows must say which one it acts on: a global "+" with a default argument silently picked the 3D view. Keep one list per target (tabs) and let the target follow where the user works (press / focus / enabling a tool) – but never from a frequently fired signal (the Render View's `tool_state().changed` sync would have dragged the tab back to it).

- Exports that burn drawings in should not depend on view toggles (Show drawings) – the user asked for them explicitly (`paint_layers(always=True)`); draw at the image's own resolution (rect = the full image) since strokes are normalized to the camera-frame height.

- Network from an add-on: never on the UI thread (a thread + a queued Qt signal), respect `bpy.app.online_access` (the owner has it off – an explicit user click may still connect), and never test a real `addon_install` on the owner's PC: overwrite=True deletes the whole add-on folder first.

- A widget style sheet with `QWidget { background: … }` (headers) overrides the app style's `:checked` colour for every button inside – add `theme.checked_qss()` (and `hover_qss()`) to such style sheets.

- Operators clicked in Blender's Preferences window run with a temporary screen – `bpy.context.temp_override` raises there; anything that needs a 3D view context must be deferred to a timer (`bpy.app.timers.register`).

- QDockWidget titles ignore later font changes (they use `QApplication.font("QDockWidgetTitle")` captured at creation while the dock font equals the class font); `QDockWidget::title { font-size }` is ignored. Give docks an explicit `setFont` after `app.setStyleSheet` (see `theme._dock_title_fonts`).

- Background work in the UI thread needs a duty cycle, not just an idle check: one cached frame of a rig costs 25 ms+, so steps every 40 ms keep Blender busy almost all the time and the next mouse move feels laggy.

- An error popup must only react to program errors: many logged ERRORs are usage situations (operator poll failed, e.g. the shelf's Extrude on an armature in Edit Mode) and would make the window a nuisance – filter on traceback + exception line (`errorwin._USAGE`).

- Shelf presets are copied into the user's shelves.json once – fixing a built-in button needs `shelf_presets.UPGRADES` (old exact command → new), applied only to unchanged buttons.

- **Tests that press tool keys change shared QSettings** (`viewport/tool`, `viewport/tool_variant_*`, `viewport/toolbar` via T): snapshot `QSettings.allKeys()` at the start of a test and restore every changed / added key at the end (`_t146.py` `restore_settings`). The owner's Blender keymap is Industry Compatible – Blender keymap items in tests are not Blender's defaults.

- **Screen grabs on the owner's PC show the Claude app window** in the top-right (computer-use screenshots hide it) – an eyedropper / grab test there reads the Claude window's dark colours; test pixels in the lower-left. `QScreen.grabWindow(0, x, y, w, h)` with 125 % scaling: grab the whole screen and map by the image size instead.

- **Qt `clicked(bool)` fills the first optional parameter of a connected method** (`accept_color(close=True)` got False) – connect buttons to methods with parameters through `lambda _=False: …`.

- **Sculpt strokes from Python**: run `sculpt.brush_stroke` in EXEC with a stroke list in the hidden 3D view whose
  `region_3d.view_matrix` is the Qt view's (`override_location=True` → positions come from `mouse_event`). Element `size` is
  ignored – the radius comes from the brush / unified size, so scale that to hidden-view pixels for the call. Keys of
  OperatorStrokeElement in 5.2: name, location, mouse, mouse_event, pressure, size, x_tilt, y_tilt, time, is_start (no `pen_flip`).
- **Python operator calls suppress nested undo pushes** (`wm.op_undo_depth`): a sculpt stroke called plainly from Python makes
  no undo step at all, and `ed.undo_push` in Sculpt Mode stores nothing for the mesh. Call `bpy.ops.x("EXEC_DEFAULT", True, …)`
  (undo=True – like from the UI) for Sculpt Mode operators and for entering / leaving Sculpt Mode; without the "enter" step
  the first undo jumps to an older memfile state (another mesh) and Qt code reading the old data crashed.
- **Sculpt changes don't show in the offscreen view by themselves**: the stroke tags only Blender's own region. After a
  chunk `ob.update_tag(refresh={'DATA'})` refreshes the drawing; after undo / redo some sculpt batches stay stale (a dab of
  the undone stroke stays drawn) – one `mesh.update()` after the last step fixes it.
- **Windows pumps the thread's messages inside some operators** (sculpt undo): Qt timers fire in the middle of the operator
  while Blender swaps the data – touching RNA there crashed. `bridge.op_depth > 0` while run_op runs one; timer code checks it.
- Sculpt Mode keeps positions in its own data: `ob.data.vertices` and the evaluated mesh show the old shape until Object
  Mode – tests read coordinates after `mode_set('OBJECT')`. Removing objects with `bpy.data.objects.remove` and then
  `ed.undo` crashes Blender – tests delete with `object.delete`.

- Never name a Qt widget attribute after a Qt method (`self.font`, `self.size`, `self.width` …): it hides the method and `hasattr` checks on it are always true.

- Sculpt strokes run in EXEC skip the UI's checks: Erase / Smear Multires Displacement without a Multires modifier crash Blender – `sculpt.stroke_blocker()` guards brushes like that.

- **The Qt view can't draw the sculpt tree**: `draw_view3d` is an "image render" for Blender's draw engines, so Sculpt Mode is drawn from the evaluated mesh – fine for plain meshes (tag DATA after each stroke), but Multires grids and Dyntopo BMesh changes don't show. Borrowing pictures (`screen.screenshot_area` of a hidden helper window, 0.84) costs ~35 ms per frame; embedding a real Blender window (0.85, sculptview.py) is native speed (draw handlers only see the overlay buffer; the minimized main window is never drawn).

- Qt `underMouse()` stays False after a popup closes until the mouse leaves and re-enters – hover drawing should test the cursor position against `rect()`.

- **Embedding a Blender window in Qt** (`QWindow.fromWinId(hwnd)` + `createWindowContainer`) works: Blender keeps drawing and handling input in the child. But Windows leaves the Win32 keyboard focus in the native child when a Qt widget is clicked – SetFocus the Qt window on Qt mouse presses. Blender re-enables a Sculpt Mode view's tool header after window setup – hide it again later.

- **RNA updates of a space in another window need that window in the context**: setting `show_region_header` etc. on a freshly created window's space while `bpy.context.window` is NULL (e.g. right after another window was closed) crashes in `ED_area_init` → `WM_window_get_active_workspace`. Wrap such changes in `temp_override(window=…, screen=…, area=…)`. `RegionView3D.view_matrix` is only computed at draw time – read `view_rotation` / `view_location` / `view_distance` for a view that may not have drawn yet.

- **Qt drawing inside Blender's own view**: a POST_PIXEL draw handler can paint with QPainter into a QImage and show it as a GPUTexture (`gpu.types.Buffer('FLOAT', n, numpy_array)` takes the array directly; flip rows; premultiplied alpha → `blend_set('ALPHA_PREMULT')`). Colours match the Qt view.

- **Never key a cache / rebuild check on `id()` of a bpy wrapper** – `id(bpy_struct)` changes between calls (a new Python object each time); use `as_pointer()`. **Avoid `QApplication.setOverrideCursor` for drags** – if the widget dies mid-drag the override stays for the whole app; set the cursor on the grabbing widget instead.

- **Don't re-parent a widget that holds an embedded native window** (createWindowContainer of a foreign HWND) – take the window out first (sculptview.layout_changing) and embed it again after the layout change.

- **Blender routes key events to its active window** – an embedded child window that only got SetFocus() receives the keys but Blender drops them; send it WM_ACTIVATE (WA_ACTIVE) too (a click does that inside Blender). `bpy.context.visible_objects` only exists in a context with a 3D view – fall back to `view_layer.objects` + `visible_get()`.

- **`SpaceView3D.show_region_*` set from Python takes effect – and reads back – only after the area redraws**: tag_redraw() the area, and don't treat the old value read right after as a user change.

## 4. Workflow (how changes were made and tested)

### Edit → deploy → test on the owner's PC
The cloud workspace has the repo at `/home/claude/blender-qt-shell`. The owner's PC is linked; the
add-on folder there is connected:

`C:\Users\uzivatel\AppData\Roaming\Blender Foundation\Blender\5.2\scripts\addons\qt_shell`
(device shell: `$HOME/mnt/qt_shell`; temp folder: `$HOME/mnt/Temp` = `%TEMP%`)

1. Edit in the repo; check syntax / undefined names (`ast` check script).
2. Copy changed files into a **new unique folder** `/mnt/user-data/outputs/<name>_<timestamp>/`
   (re-using a staging path can deliver stale content).
3. `device_commit_files` with `force=true` to the add-on folder, then verify sizes with `wc -c` on the device.
4. Reload in the running Qt Shell: Console tab → `import qt_shell.devreload as _r; _r.go()` (Enter).
   Or restart Blender.
5. Test with computer use (Blender 5.2 = `blender.exe` must be granted).

### Computer-use gotchas
- The **Claude window overlays the top-right of the screen** – clicks there land in Claude, not Blender.
  Use console commands instead of clicking top-right buttons.
- `computer_open_application("Blender")` can **start a second Blender** instead of focusing the running one.
- `computer_type` pastes via clipboard → it does **not** trigger key handlers (auto-complete); use
  `computer_key` for single keys.
- Ctrl+Space outside the Text editor = maximize viewport (window shortcut).
- **Don't reload / click while the owner is working in Blender** – deploy the files and tell them how to reload.

### Commit / release
- Commit messages end with the `Co-Authored-By` / `Claude-Session` lines from the session.
- Push to `main` works from the session. **Creating releases via the API is not possible (403)** – write
  the release text (English) and the owner publishes it: tag `vX.Y.Z` on `main`, title
  `Qt Shell X.Y.Z – …`, attach `qt_shell.zip` (zip of the `qt_shell/` folder without `__pycache__`).
- Bump `bl_info["version"]` before building the release zip.
- Release text format (current): tag + title in one code block; body with `## New` / `## Fixes` /
  `## Improvements` and `## Install` – see `CLAUDE.md`.
